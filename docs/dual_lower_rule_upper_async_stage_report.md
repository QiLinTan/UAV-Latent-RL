L0：DSLPIDControl → T3 asymmetric_rpm → 四电机
L1：普通 BC MLP → T3 asymmetric_rpm → 四电机

## 已落地的工程改进

### 1. 双基线冻结

生成了 `dual_lower_baseline_v1` 清单，记录：

- DSLPID 源码哈希；
- 首版 BC Actor 检查点哈希；
- 数据集 SHA-256；
- Actor 输入输出和网络结构；
- T3 电机物理参数；
- 控制频率和 ReferencePacket 合同；
- 禁止在对照实验中修改的项目。

DAgger 检查点明确排除在主线之外。

### 2. 可重复的异步通信故障层

新增通信故障模型，支持：

- 上层更新频率；
- 固定延迟和随机抖动；
- 随机丢包；
- 连续突发丢包；
- 重复包；
- 乱序延迟；
- 队列深度、接受、丢弃和拒绝原因统计。

`AsyncReferenceBuffer` 现在分别统计：

- 接受包；
- 过期版本；
- 接收时间乱序；
- 总拒绝包。

### 3. 统一双下层评估器

两个控制器使用完全相同的：

- 环境和初始状态；
- ReferencePacket；
- 随机种子；
- 传感器噪声；
- 观测延迟；
- 动作延迟；
- 外部扰动；
- 质量、推力和电机效率变化。

从而能够区分：

```text
双方失败 → 共享环境、参考接口或共同能力边界
仅 L0 失败 → DSLPID 对该工况更敏感
仅 L1 失败 → 学习型下层能力缺口
```

### 4. 修复 ReferencePacket 时钟边界

冒烟测试发现，`step / frequency` 与 `step * control_dt` 可能相差一个浮点
ULP，使刚发布的包偶发被判断为“尚未开始”。现统一使用下层运行时钟：

```text
now = runtime_step * control_dt
```

修复后理想通道不再出现虚假的单步降级。

## 下层鲁棒性矩阵

共运行 192 个回合，每个 profile 包含悬停、直线、缓弯、初始组合姿态、
初始水平速度和组合冲击，使用两个随机种子和两个下层控制器。

| profile | L0 DSLPID | L1 BC Actor | 主要结论 |
|---|---:|---:|---|
| 标称 | 通过 | 通过 | 两者标称成功率与恢复率均为 100% |
| 推力系数 −10% | 通过 | 通过 | 两者均能补偿整体推力变化 |
| 质量 +10% | 未通过 | 未通过 | Actor 全部姿态越界；教师在组合冲击失败 |
| 2 步观测延迟 | 未通过 | 通过 | Actor 100% 通过；教师未达到严格恢复判据 |
| 中等传感器噪声 | 未通过 | 通过 | Actor 对当前噪声更稳 |
| 2 步动作延迟 | 未通过 | 通过 | Actor 100% 通过；教师存在持续恢复残差 |
| 单电机效率 90% | 通过 | 未通过 | Actor 出现持续位置和姿态偏置 |
| 组合轻度不确定性 | 未通过 | 未通过 | 两者均超过当前能力包线 |

因此不能简单说“神经网络下层比 PID 差”：

- Actor 在观测延迟、动作延迟和传感器噪声下优于当前 DSLPID；
- DSLPID 在单电机效率下降下明显优于 Actor；
- 两者在质量变化叠加组合冲击时都存在问题。

## 能力边界细化

额外运行 84 个阈值扫描回合。

### 单电机效率

在悬停、组合初始姿态和组合冲击三个工况全部通过的条件下：

| 控制器 | 最低已测通过效率 | 首个已测失败效率 |
|---|---:|---:|
| L0 DSLPID | 90% | 尚未测到 |
| L1 BC Actor | 98% | 97% |

这直接说明首版 Actor 没有学到单电机效率不对称下的持续补偿。

### 质量变化

在所选组合冲击下：

- 标称质量时两个控制器都通过；
- 质量增加 0.5% 时两个控制器都触发姿态边界；
- 该值只是当前组合冲击和终止阈值下的开发边界，不是理论物理极限。

这个结果意味着质量随机化不能只加入 Actor 训练；首先需要一个在相同工况下
也能恢复的鲁棒教师或安全控制基准。

## 规则上层异步验证

共运行 192 个回合，覆盖直线、缓弯、初始组合姿态和组合冲击。

### 标准异步包线

以下条件下，两个控制器均达到 100% 功能成功率和 0% 失稳率：

- 上层频率：15、10、5、2 Hz；
- 固定延迟：100、200 ms；
- 随机丢包：10%、30%；
- 连续丢包：500 ms；
- 连续丢包 1250 ms并触发 ReferencePacket 过期；
- 重复包和乱序包。

1250 ms 连续丢包时：

- 两个控制器均观察到 8 次过期和 8 次通信恢复；
- 降级动作均单调向 T3 悬停零点收敛；
- L0 最大恢复动作跳变为 0.139；
- L1 最大恢复动作跳变为 0.152；
- 两者仍保持 100% 功能成功率。

重复和乱序工况中：

- 注入 480 个重复包和 384 个乱序延迟包；
- 缓存拒绝 832 个旧版本/重复包；
- 没有让旧包覆盖新包；
- 两个控制器均保持 100% 功能成功率。

这直接支持以下系统特征：

> 上层以低频输出带时间戳和有效期的未来参考序列；下层以 120 Hz 独立执行；
> 通信短时中断时继续使用缓存序列，序列过期后降级至悬停等价动作，通信恢复
> 后重新接管。

### 扩展极端边界

极端 profile 同时包含：

```text
100 ms 延迟
+ 40 ms 抖动
+ 20% 随机丢包
+ 1250 ms 连续断流
+ 重复
+ 乱序
```

结果：

- L0 标称成功率为 25%；
- L1 标称成功率为 0%；
- L1 最大通信恢复动作跳变为 0.788；
- 两者主要在直线和缓弯恢复接管时发生姿态越界。

因此扩展极端门槛未通过。下一步需要的是参考序列连续性检查和恢复接管桥接，
而不是修改 Actor 权重来掩盖通信接口问题。

## 当前开发路线判断

### 可以继续的工作

可以在标称仿真中开始学习型上层，因为：

- L1 的标称、推力变化、延迟和噪声核心门槛通过；
- 规则上层标准异步链路通过；
- 学习型上层可以继续使用完全相同的 ReferencePacket 输出合同；
- 下层保持冻结，可将新增性能归因于上层。

### 暂时不能声称或执行的工作

- 不能声称下层具备部署级质量和电机故障鲁棒性；
- 不能进入 sim-to-real；
- 不能将极端组合通信故障表述为已解决；
- 不能开始 TD3 下层微调；
- 不能直接将任意 latent 接入电机 Actor。

## 下一步

建议并行推进两条线：

1. 主线：在标称仿真中接入学习型上层，但输出仍为 ReferencePacket；规则
   上层继续作为固定对照。
2. 鲁棒性支线：为质量变化和单电机效率不对称建立新的数据覆盖与安全基准；
   冻结的 v1 Actor 不覆盖修改。
3. 异步支线：为极端通信恢复增加参考连续性验证和渐进接管，再重复极端
   profile。
4. 只有学习型上层稳定后，才在相同输出合同下比较 affordance 与 latent
   的上层感知增量。
