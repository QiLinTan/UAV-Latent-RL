# 让 no_route 在多个训练 seed 上稳定成功的实验设计

## 为什么先改变成功样本的获得方式

当前 Stage 0 固定从 7 m 外出发，20/20 地图直接朝目标飞会撞上 1 棵路线阻挡树；使用真值地图绕行的 K1 诊断控制 20/20 成功。seed 42 在 Stage 0 的 422 局中有 88 局训练成功，而 43–45 的 707/733/714 局均没有训练成功；它们的选中策略在独立的 Stage 0 训练地图复核中也均为 0/20 入 1.2 m 球。成功回放采样率目前为 0.20，但这三个 seed 的成功 buffer 为空。动作执行和 GRU 回放路径核查一致；尚不能证明某个训练代码错误造成分化。

因此首个**训练机制消融**应只改变起点分布，让策略先反复获得真实的 0.2 m 成功转移，再逐渐延长路线并引入挡路树。它与从目标附近向外扩展起点的[反向课程研究](https://proceedings.mlr.press/v78/florensa17a.html)方向一致；本文的距离档位和阈值是基于本项目提出的待检验配置，不是论文给出的通用常数。以前提出的“先加入剩余时间观测”仍有合理依据，但 Stage 0 的新证据把首批成功轨迹覆盖提升为第一优先级。两个改动应分轮测试。

## 第一轮：只做起点距离课程

冻结 `no_route` 的 TD3、h8、圆盘动作、K1、地图生成、障碍数量规则、奖励参数、成功半径 0.2 m、碰撞/越界/timeout 惩罚和原有 5000 步随机预热。新增训练重置模式：先按**原始 [-3.5, 0, 1] 起点**生成完整 Stage 0 随机森林，再在该地图的一条无碰撞可行路线中，按到目标的剩余路线长度选择重置点；路线和树坐标只在重置器内使用，不进入 Actor 观测，也不产生教师动作。保留完整原起点回合作为训练混合和独立评估。

候选距离档位为：L0 目标外约 0.35–1.2 m（确保未在 0.2 m 成功球内）、L1 1.2–2.5 m、L2 2.5–4.5 m、L3 4.5–7 m，最后回到完整 7 m 原起点。用路径剩余长度选点，同时记录实际三维距离；每个点须有机体半径外安全余量，并排除树干、地图边界和成功球。初期可抽 80% 当前档、20% 原始 7 m；晋级时逐渐提高原始起点比例，避免只会完成短任务。当前档最近 100 局训练成功率达到约 70%、碰撞不超过约 20%，且至少训练 100 局后，才尝试晋级；阈值只是首轮设定，须与日志一起检验。原有按成功率推进障碍难度的 stage 机制在这个诊断阶段保持 Stage 0，等原起点 Stage 0 稳定后再恢复 Stage 1–3。

实现上，必须在地图生成**之后**放置课程起点，否则程序森林会围绕新起点重新生成，改变障碍任务。放置后将速度置零、步数置零，重算 `_prev_pos`、`_prev_goal_dist`、reference position/velocity、碰撞与 ray 观测；清空并用新位置首帧填满 8 帧 GRU 历史。检查重置后的 replay `state/action/next_state` 配对。成功判定仍使用原始三维 0.2 m 球。课程状态要随 checkpoint 保存，或明确定义重启后从日志恢复的方式。

## 对照与门槛

先在 seed 43 做小样本试验：B0 原方案仅新增诊断日志；C1 只新增起点课程。两者使用同一训练 seed、地图 family、奖励、网络和训练步预算；不要把 B0 原训练的最终指标误当成精确训练入区率，因为旧日志缺少逐步最小距离。比较前 5000 步是否出现第一条成功、2 万步内成功 replay 是否非空、每档的真实 `training_episode/min_goal_distance`、入 1.2 m 率、成功率和碰撞率。若 C1 连 L0 都没有成功，优先审查重置状态、终止条件和奖励归因，勿继续扩大距离。

小样本通过后，用固定总预算和相同模型选择规则，对 seed 42–45 跑完整配对实验。每 2000 步记录：(1) 当前档训练成功和入区；(2) 原 7 m Stage 0 地图固定种子 20 局的成功/入区；(3) 现有验证地图 0–9 用于 checkpoint 选择；(4) 验证地图 10–19 作为额外评估，不让其影响选择。原 20 局正式评估、动作幅值审计、T1/T2 分类和多步 Q 校验继续保持。建议把“至少 3/4 个训练 seed 在原起点 Stage 0 达到 ≥60% 成功、≥80% 入区”作为恢复障碍难度 Stage 1–3 的工程门槛。最终是否称为解决多 seed 问题，应在完整验证地图的 20 局正式评估中要求至少 3/4 个训练 seed 达到 ≥50% 成功，且逐 seed 报告碰撞率、T1/T2 和高度越界；这些阈值是待检验的项目决策标准，不是预期结果。报告每个训练 seed，不能只报平均值或选中的最好 seed。

## 根据观测结果分支处理

| 观测结果 | 下一项单变量实验 |
| --- | --- |
| L0 成功、跨越阻挡树时突然失败 | 固定起点距离，单独分级路线阻挡树/安全绕行难度；必要时评估少量**安全成功轨迹示范**。示范从 K1 真实 `step` 收集可执行圆盘动作与完整 h8 历史，来自许多训练地图，不在评估时提供真值路线。[连续控制示范研究](https://arxiv.org/abs/1709.10089)支持把示范当作克服稀疏成功探索的一种候选方法，但对本任务仍需独立消融。 |
| 经常进入 1.2 m、仍少有 0.2 m 成功 | 检查末端方向、速度和近目标 Q 排序；此时才独立测试近目标速度跟踪权重（成功绕行轨迹累计约 32.7 原始奖励单位）。不要同时改课程。 |
| 成功 replay 已非空、训练成功持续增加，原起点仍不会成功 | 检查真实成功轨迹在 replay 的距离分布和 Critic 多步校准；再单独测试按距离分层采样、连续 3–5 步目标或示范。多步 TD3 要保留 episode 边界、真实动作和 h8 窗口，并处理离策略偏差；不能直接把单步 Q 值当作强制多步动作序列的价值。[TD3 原论文](https://proceedings.mlr.press/v80/fujimoto18a.html)是当前双 Critic/延迟更新的依据，无需先整体换算法。 |
| 有时距目标很近，但临近 timeout 的价值判断混乱 | 单独加入归一化剩余时间到 Actor/Critic 观测后从头训练。旧核查已证明同一 917D 观测会有不同剩余时长；这是状态别名的直接证据，但尚未证明它是 43–45 的主要原因。 |

先补正训练记录：Actor 梯度只在真实 `actor_updated=True` 时汇总，另记每日志窗口的更新次数；Critic 记录裁剪前范数、裁剪比例和按目标距离分组的 TD 误差。旧日志里 seed 43–45 的 Actor 梯度“全 0”由采样相位造成，不能据此调整优化器；Critic 裁剪前梯度频繁超过阈值 1，也不足以直接宣告数值爆炸。第一轮保留网络大小、学习率和裁剪阈值，让数据分布消融的归因清楚。

当前不优先做 HER：固定目标、障碍碰撞和终端事件使目标重标记需要重新定义成功、碰撞与整段奖励；直接重标记可能产生与原任务不一致的样本。[HER 原论文](https://arxiv.org/abs/1707.01495)针对目标条件化的稀疏奖励学习，应用到本项目需要另立实验。Full/DSLPID 微调也应等 K1 在多个训练 seed 上稳定后再做；K1 的可达性试验未覆盖 Full 动力学。

## 已实现的第一轮训练消融（startcurr_v1）

新增 `upper_dslpid_recurrent_multitree_terminal_v2_noroute_startcurr_v1_h8_k1` 模式。仅训练环境重置器变化：森林仍围绕原始起点生成，之后在同一张图的安全路径上选择 L0–L3 起点。对应路径剩余长度档位为 0.35–1.2、1.2–2.5、2.5–4.5、4.5–7 m；混入原 7 m 起点的概率依次为 20%、20%、30%、50%，最后全为原起点。各档只统计该档回合，在至少 100 局且最近 100 局成功率 ≥70%、碰撞率 ≤20% 时晋级。起点离成功球至少 0.3 m，并经过几何余量和 PyBullet 接触检测。策略输入仍是原 917D h8 观测，不包含路径或树真值。

这只是 Stage 0 的独立消融：挡路树难度固定在 Stage 0，原障碍课程计数不推进；暂不解锁 Stage 1–3。评估回调使用普通 K1 环境与原始起点、原验证地图，checkpoint 选择仍按原 preset。`--load_checkpoint` 在新模式下禁止，因为训练 replay 与起点课程状态未实现完整续训恢复；应从头启动一次新的训练。

先运行 seed 43 的完整 120k 训练，并在 20k、40k 等评估点观察早期日志：

```bash
/home/tequila/miniconda3/envs/drones/bin/python -m scripts.run_change_td3 \
  upper_dslpid_recurrent_multitree_terminal_v2_noroute_startcurr_v1_h8_k1 \
  --seed 43 --total_steps 120000
```

输出自动按训练 seed 隔离在 `runs/upper_dslpid_recurrent_multitree_terminal_v2_noroute_startcurr_v1_h8_k1_seed43`、同名 `checkpoints/` 和 `analysis_outputs/` 路径。对照 43–45 时只改 `--seed`，顺序运行：

```bash
for seed in 43 44 45; do
  /home/tequila/miniconda3/envs/drones/bin/python -m scripts.run_change_td3 \
    upper_dslpid_recurrent_multitree_terminal_v2_noroute_startcurr_v1_h8_k1 \
    --seed "$seed" --total_steps 120000 || break
done
```

日志中的 `env/start_curriculum_level` 是当前档位（0–3 为短距离档，4 为全原起点），`env/start_curriculum_episode_level` 是刚结束回合的档位；`env/start_curriculum_is_band`、`env/start_curriculum_is_original`、`env/start_curriculum_is_fallback` 标记起点来源；`env/start_curriculum_initial_distance` 是真实初始三维距离。`env/training_episode/min_goal_distance`、`env/training_episode/entered_guidance_1p2` 与 `env/done_reason/success` 用来判断是否获得第一条成功轨迹以及是否真正进入引导区。切勿把近起点训练成功率直接当作原 7 m 策略成功率；仍应看原起点验证地图评估。

验证：同 seed 地图几何完全相同；重置点、GRU 历史、初始目标距离、第一步 progress 奖励和碰撞状态通过物理环境测试；25 项相关测试通过；2 步与 200 步训练入口冒烟运行通过。尚未进行完整训练或证明多 seed 成功率会提高。
