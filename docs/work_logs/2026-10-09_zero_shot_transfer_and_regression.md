# 冻结策略的复杂障碍与 Full 零样本评估

## 结论

四个 `startcurr_v1` 选中 checkpoint 已单独冻结。在原始 7 m 起点、环境 seeds 0–19 上，**Full Stage 0 为 80/80 成功**，与此前同一批 checkpoint 的 K1 Stage 0 原始起点复核（80/80）一致；当前没有证据表明 K1→Full 的参考跟踪差距是 Stage 0 的主要瓶颈。相反，K1 的复杂障碍成功率随阶段增加从 Stage 1 的 69/80、Stage 2 的 48/80 降到 Stage 3 的 14/80。Stage 3 的 66 次失败中有 59 次未进入三维 1.2 m 引导区，60 次为碰撞。因此下一阶段应优先扩展障碍课程和局部避障能力，同时单独处理训练后期的策略回退；目前不需先修改目标球奖励或立即开展 Full Stage 0 微调。

这只是当前地图族、当前控制器和 20 张环境地图的零样本结果。四模型 Full Stage 1–3 尚未完整测试；下文另补了 seed 45 的 Full Stage 3 定向对照。Full Stage 0 成功不能外推到复杂障碍。所有 20 张地图在每个阶段的环境验证中均被标记为 `primitive route is reachable`；这说明存在几何路线，但不等于给出了当前控制器的完整动态可行性证明。

## 冻结与评估口径

训练 seeds 42、43、44、45 的选中网络分别来自 56k、90k、68k、86k。`model_final` 是恢复 `model_best` 后的选中策略，不是最后一次梯度更新网络。四份完整 checkpoint（Actor、Critic、优化器及选择记录）复制到 `checkpoints/startcurr_v1_frozen_20261009/`，清单记录每个文件 SHA-256；评估后重新校验 20/20 文件一致。零样本评估没有执行训练更新。

每个训练 seed、每个设置固定运行环境 seeds 0–19 共 20 局，均从 `[-3.5, 0, 1]` 原始起点出发，成功仍指进入三维半径 0.2 m 球。K1 Stage 1–3 和 Full Stage 0 均使用训练地图族 `procedural_forest_multitree_train_v2`。复杂障碍阶段分别强制为 2、3、5 棵路线阻挡树，并在环境构造后禁用该地图原有的 20% 简单阶段混合；每次 reset 都检查实际阶段、实际阻挡树数量及起点。Stage 0 是 1 棵路线阻挡树。日志里的 `eval/curriculum_stage` 沿用训练端课程计数，可能显示 0；实际阶段以每个运行目录的 `protocol.json`、reset 断言和阻挡树数量为准。

| --- | ---: | ---: | ---: | ---: | ---: |
| 42 | 20/20 | 17/20 | 13/20 | 2/20 | 20/20 |
| 43 | 20/20 | 16/20 | 7/20 | 4/20 | 20/20 |
| 44 | 20/20 | 16/20 | 15/20 | 3/20 | 20/20 |
| 45 | 20/20 | 20/20 | 13/20 | 5/20 | 20/20 |
| 四模型合计 | 80/80 | **69/80** | **48/80** | **14/80** | **80/80** |

| 设置 | 入 1.2 m 球 | 碰撞 | timeout | 失败且未入 1.2 m 球 | 失败但已入 1.2 m 球 |
| --- | ---: | ---: | ---: | ---: | ---: |

| K1 Stage 2 | 51/80 | 29 | 3 | 29 | 3 |
| K1 Stage 3 | 21/80 | 60 | 6 | 59 | 7 |
| Full Stage 0 | 80/80 | 0 | 0 | 0 | 0 |

Stage 3 的 59 次入区前失败由 58 次碰撞和 1 次 timeout 组成；其余 7 次入区后失败为 2 次碰撞、5 次 timeout。碰撞窗口诊断把 Stage 1/2/3 的碰撞分别标为 `A/C = 3/8、11/18、21/39`。A/C 是按动作和净空变化得到的启发式标签，不等于人工验证的全部致因。复杂障碍下主要退化发生在**到达目标附近以前**，末端入球是次要失效来源；Stage 3 不能靠单独加强 terminal shaping 解决。Stage 3 的 20 张地图中，环境 seed 11 是四模型中 3 个成功，环境 seeds 1、3、4、6、7、8、12、13、14 均 0/4 成功，说明地图难度与策略差异都值得在课程设计时保留分层统计。

Full Stage 0 四个策略各 20/20，平均位置跟踪 RMSE 依次约 `0.0218、0.0244、0.0239、0.0182 m`，平均速度跟踪 RMSE 依次约 `0.0639、0.0777、0.0905、0.0636 m/s`。Full 并非完全等同于 K1；这里只能说当前 Stage 0 成功判据未暴露出阻断迁移的控制差距。参考跟踪表现和更难障碍下的安全裕度需要另行验证。

## 历史 Full Stage 3 的口径复核

用户记得的旧成绩确实存在：`upper_dslpid_recurrent_multitree_v4_1` 默认使用 **Full/DSLPID**，所选 `model_best` 来自 88k，在当时标为 Stage 3 的周期评估中为 **9/10 成功、1/10 timeout、0 碰撞**。但该评估使用 `procedural_forest_validation_v1`：24 棵树，其中五棵挡路树按 `fixed_safe_five` 固定安全布局排列；此验证地图不启用路线数量课程，`curriculum_stage=3` 是训练端阶段标签，并不表示验证地图在 0→3 阶段逐渐变难。本轮随机 Stage 3 使用 `procedural_forest_multitree_train_v2`：36 棵树、五棵挡路树随机排列，并关闭 20% 简单阶段混合。这两种“五棵树”不是同一任务分布。

在**当前代码、同一个新选中策略 seed 45、同一 Full 动力学**下进行直接对照：固定验证布局 **20/20 成功**；随机 Stage 3 **5/20 成功、15/20 碰撞**。同一策略在 K1 的随机 Stage 3 也是 5/20，成功的环境地图与 Full 有 4/5 重合。这个对照把当前主要退化定位到随机复杂障碍布局及其避障泛化，而不是“Full 完全飞不过五棵树”或“末端不能入球”。它只覆盖一个训练 seed，其他三个 Full Stage 3 仍待验证。

旧 `v4_1` 在 88k 以前的训练日志中，Stage 3 回合里实际五棵挡路树的训练成功为 8/27；这表明它并非从未在随机五树地图成功，但含探索噪声的训练比例不能与正式零样本评估直接比较。旧 checkpoint 在**当前代码**复跑两类五树地图均为 0/20，不能据此否定历史 9/10：该模型训练后，range-ray 起点修复改变了 Actor 的传感器输入协议，当前运行时并非旧训练环境的精确重现。旧奖励、h4 历史和地图族也与当前模型不同。历史记录应作为“固定五树 Full 可以成功”的证据，而非当前随机 Stage 3 已经解决的证据。

因此下一轮训练应在保留已学会的原起点 Stage 0 能力的同时，逐级引入随机两、三、五棵挡路树；各阶段的评估和 checkpoint 选择必须包含**对应随机地图、关闭简单阶段混合**的固定环境种子，另把 `fixed_safe_five` 作为单独的跨地图对照。先保持奖励、rayfix、动作接口和网络不变，以判断障碍课程是否足够；若随机 Stage 3 仍以 A/C 类碰撞为主，再独立测试局部避障控制、结构化空间记忆或多步价值改进。

## 训练后期回退：独立审计

以下只读取训练时的**原始周期评估**，每次固定 10 张评估地图；日志最后同一步的第二条记录是恢复 `model_best` 后的再评估，已排除，不能当作原始末期网络。它们和上面的冻结 checkpoint 20 局结果不是同一个网络比较。

| seed | 选中步/起点档及当时成功 | 最后原始步/起点档及成功 | 末次碰撞/timeout | 选中后最差成功 |
| --- | --- | --- | --- | ---: |
| 42 | 56k / L2，10/10 | 68k / L3，1/10 | 4/10、5/10 | 0/10 |
| 43 | 90k / L4，8/10 | 120k / L4，6/10 | 4/10、0 | 5/10 |
| 44 | 68k / L3，10/10 | 84k / L4，5/10 | 5/10、0 | 2/10 |
| 45 | 86k / L4，10/10 | 120k / L4，5/10 | 3/10、2/10 | 3/10 |

seed 42 的明显崩溃与 L2→L3 晋级时间接近，seed 44 在 L3 不变时已经由 10/10 掉到 74k 的 4/10、78k 的 2/10，之后才到 L4；seed 45 在 L4 不变时 104k 掉到 3/10，112k 又回到 10/10，120k 再降至 5/10。seed 43 同在 L4 时也在 5/10–8/10 间波动。这排除了“全部回退只是起点课程切换瞬间造成”的单一解释，但还不能据此判定具体的 TD3/GRU/Replay 机制。TensorBoard 中 seed 43/45 后期 Critic batch loss 很低，原始评估仍会下滑；低训练 batch loss 不能证明部署策略稳定。此前近目标 Q scan 也未发现可靠的局部价值排序，但现有证据不足以把该问题直接归因为这些后期回退。

当前 `model_best` 选择和冻结流程有效地保住了可用策略，应继续使用。下一次训练机制实验宜增加固定 held-out 地图的周期评估、保留晋级前后和回退窗口的**原始网络快照**，在同一组状态上做动作、Critic 与回放分布对比；必要时再分别测试更平缓的课程晋级、保守更新或更稳健的 checkpoint 选择。应单独做这些消融，不与障碍课程扩展或 Full 微调同时修改，避免无法归因。
